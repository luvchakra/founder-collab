# Test Coverage Index

Single source of truth for coverage state, across both automated scripts and
documented cases. Update this table in the same commit as any change to a test-case
file or `scripts/test-*.mjs`. See `TESTING_STRATEGY.md` for the policy.

**First execution pass:** 2026-09-08, see `../EXECUTION-2026-09-08.md` for what was
actually run/traced against `main` and what it found (four real gaps, none caught by
the existing automated suite: ADR-9's grace-period expiry is never invoked by anything,
`fsm`'s `cancelJob()` leaks reserved inventory stock forever, GST GSP credentials are
stored in plaintext rather than encrypted like BYOK keys, and `requireModule()` — named
by `CLAUDE.md` as a required enforcement layer — doesn't exist in the codebase).

**Second full audit pass: 2026-09-12.** The prior pass (2026-09-09) was 3 days and
80-90+ commits per major area stale by the time of this pass — CRM's WonderArc backlog
(74 stories), Compliance's global-tax expansion (P1 EU VAT + US, on top of full India
GST), Discovery's Offering-Centric backlog (39 stories), the Platform Admin Portal
(brand-new, 8 P0 sections), and 29 cross-module Integration-backlog stories had all
shipped with zero corresponding test-doc updates. This pass traced each module's own
dated audit log (`docs/design/{crm,compliance,discovery-offering,platform-admin-portal,
integration}-backlog-audit.md`) against its test-case file and corrected/added cases
accordingly — see each file's own top-of-file note for specifics. **Recurring theme
across every module:** a large amount of new tenant/business-scoped schema shipped
with real, executed RLS-script coverage in `crm`/`gst`/`platform`, but **zero**
automated RLS-script coverage in `discovery` (13 new tables) and only partial coverage
of new cross-module contract functions in `fsm`/`inventory` — flagged per-file, not
just here.

Status values: `Automated` (real script/test in CI path) · `Documented` (manual case
file exists) · `Both` · `Partial` · `Not started`.
